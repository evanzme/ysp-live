# 央视频全频道 IPTV 直播网关 (ysp-live v8.0)

> **极简·纯粹·单端口**：集成了真 4K/8K 超高清、7 天时移回看、换台毫秒秒开、全自动故障平滑兜底的单文件 IPTV 代理服务。

---

## 🌟 特性亮点

* **📺 真 4K / 8K 超高清**：原生支持 `CCTV-4K`、`CCTV-8K`、`CCTV-16 4K` 及主流央视频道高码流（50fps、8~12 Mbps），色彩细腻无拖影。
* **⏪ 7 天时移回看 (Catchup)**：完整集成标准时移协议，完美兼容 TiviMate、Apple TV (APTV)、PotPlayer、Kodi 等主流播放器随意拖动进度条倒回播放。
* **⚡ SWR 毫秒秒开微缓存**：引入工业级 Stale-While-Revalidate 机制，15 秒窗口内切台瞬间出画面，彻底消除黑屏转圈。
* **🛡️ 直播边缘防抖 (Live Edge Holdback)**：自动为起播分片留出 6 秒安全缓冲期，根治传统流媒体“刚起播 3 秒就卡一下”的通病。
* **🚀 单文件、单个端口**：不需要运行多套软件，没有第三方依赖，一个 `:8767` 端口搞定播放列表、视频分片、EPG 订阅与控制面板。
* **📦 纯单文件、两大纯净分类**：默认内置全部 64 路高清频道。严格划分为两大清晰分类：**央视（30路）** 与 **卫视（34路）**。
* **🐳 极致轻量 Docker**：基于 Python 3.12 Alpine 构建，镜像大小**仅约 21 MB**，内存占用极低。

## 🚀 快速上手与部署运行

本项目采用**纯单文件架构**，原生支持 Python 标准库，**无需执行任何 `pip install` 安装第三方包**。你可以根据自己的设备与使用习惯选择以下三种方式之一：

---

### 方式一：Python 原生直接运行（轻量、便捷、零依赖）

适合在 macOS、Linux VPS、软路由或 Windows 终端直接运行。

#### 1. 前置环境要求
* 系统安装有 Python 3.10 或更高版本（执行 `python3 --version` 确认）。
* **零外部依赖**：全部基于原生标准库开发，无需安装任何 pip 模块。

#### 2. 前台启动（适合快速测试）
进入脚本所在目录，直接执行：
```bash
python3 ysp-live.py
```
> 默认监听 `0.0.0.0:8767`。控制台会打印就绪信息及全频道订阅地址，按 `Ctrl + C` 可随时退出。

#### 3. 常用启动参数与自定义
```bash
# 自定义监听端口（例如改为 8080）
python3 ysp-live.py 8080

# 绑定指定 IP（例如仅允许本地回环访问）
python3 ysp-live.py 8767 --bind 127.0.0.1

# 自定义内存分片缓存大小（默认 100MB，单位 MB）
python3 ysp-live.py 8767 --cache-mb 200

# 纯 1080p 备用模式（跳过设备协议握手，适合弱网或低配设备）
python3 ysp-live.py 8767 --no-4k
```

#### 4. 生产环境后台常驻运行（Linux / macOS）
若希望关闭终端窗口后程序依然在后台持续提供服务：
```bash
# 启动后台常驻进程，并将日志重定向到 ysp.log
nohup python3 ysp-live.py > ysp.log 2>&1 &

# 实时查看运行日志
tail -f ysp.log

# 停止后台服务
pkill -f ysp-live.py
```

### 方式二：Docker 一键运行（推荐）

解压压缩包后，目录下包含：
* `Dockerfile`
* `docker-compose.yml`
* `ysp-live.py`

#### 1. 一键构建并启动
进入文件所在目录，直接执行命令搞定一切：
```bash
docker compose build --no-cache && docker compose up -d
```

#### 2. 查看运行日志确认
```bash
docker logs -f ysp-live
```
> 控制台输出 `ysp-live v8.0 启动成功: 64 个独立频道 (央视 30 路, 卫视 34 路)` 即表示完全就绪！按 `Ctrl + C` 可随时退出日志追踪（容器仍在后台运行）。

#### 3. 常用运维
```bash
docker compose restart   # 重启服务
docker compose down      # 停止服务（设备身份与缓存保留在 ./data，不会丢失）
```

#### 4. NAS 设备（群晖 / 威联通 / 软路由）部署贴士
* **数据持久化与写权限**：挂载的 `./data` 目录用于持久化存储电视设备指纹（重启无需重新向云端握手）。
  * **通过 SSH 命令行运行**：Docker 会自动创建具有合适权限的 `data` 目录，无需任何额外设置。
  * **通过 NAS 网页管理器手动创建文件夹**：若在群晖 File Station / 威联通面板中手动新建了 `data`，建议右键赋予读写权限，或在终端执行 `chmod -R 777 ./data`。
* **零权限防崩保障**：底层已内置全自动容错降级机制，**即使 NAS 未赋予写入权限或设为只读，服务也会自动降级至纯内存运行，电视播放完全正常、绝不崩溃退出现象**。
* **极速网络模式**：如需追求极致 4K 吞吐并减免 NAT 开销，可将 `docker-compose.yml` 中的 `network_mode: host` 注释去掉。

## ❓ 常见问题 (FAQ)

#### Q1: 刚启动时，为什么控制台显示 `4K就绪中`？
> 脚本首次启动时需要在后台与云端进行约 5~10 秒的安全协议握手与 4K 预热。握手期间请求会自动平滑走 1080p 备用流；几秒后握手完成，会自动切换到真 4K 模式，完全无感知。

#### Q2: 家里多台电视同时看同一个频道会卡吗？
> 不会。服务内置了 100MB 内存分片缓存池，当客厅电视和卧室 iPad 同时看同一场球赛时，第二台设备会直接命中本地内存缓存直出（毫秒响应），既不浪费带宽，也不会触发上游风控限流。

#### Q3: 如何自定义频道列表或修改台标？
> 频道列表与台标已全部内置在 `ysp-live.py` 顶部的 `DEFAULT_CHANNELS` 中，直接用文本编辑器搜索对应频道名修改即可。

#### Q4: NAS 部署时，./data 目录需要写权限吗？如果权限受限会怎样？
> 服务会尝试在 `./data` 中保存设备注册信息（重启不换设备身份）。底层已内置容错防御机制：**即使 NAS 存储为只读或未开放写权限，服务会自动优雅降级为纯内存运行，电视播放与秒开完全不受影响**，绝对不会报异常崩溃。如果希望持久化保存，执行 `chmod -R 777 ./data` 即可。
